功能

把「传个文件」这件事，做到不用思考

不需要设备配对码，不需要复制粘贴链接，也不需要在两台设备上装同一个云盘客户端。打开就能看到对方，点一下就开始传。

局域网直连，跑满带宽

同一 Wi-Fi 下点对点传输，数据包不经过任何第三方服务器，千兆局域网里能跑到硬盘和网卡的极限。

工作原理

四次握手，剩下的交给局域网

YiDrop 使用一套轻量的 REST 协议在设备之间通信：发现、握手、确认、传输，全程加密，全程可中断。

  1. 发现附近设备

    应用启动后在局域网内广播并扫描，自动列出正在等待接收的设备。不需要输入 IP，也不需要配对码。

  2. 建立加密通道

    两台设备各自动态生成 TLS/SSL 证书，通过 HTTPS 建立连接。传输内容只有发送方和接收方能看到。

  3. 对方确认接收

    接收端会看到发送方名称与文件清单，可以选择接受、逐个挑选，或者直接拒绝。

  4. 直连传输并实时显示进度

    文件从一端直接流向另一端，界面实时显示文件名、总大小与当前速度，随时可以取消。

两台设备之间发生了什么

一次典型的文件传输，链路大概是这样：

设备 A HTTPS · 59420 设备 B

只有一个端口需要放行。如果收不到文件，先看防火墙是否允许 TCP/UDP 59420 的传入连接，并确认路由器上的 AP 隔离已关闭。

从源码构建

仓库使用 Flutter（配合 fvm 锁定 3.24.5）与 Rust 工具链，克隆时记得带上子模块。

# 1. 克隆项目（含子模块）
git clone --recursive https://github.com/lingyicute/YiDrop.git
cd YiDrop

# 2. 拉取依赖
fvm flutter pub get

# 3. 按平台构建
fvm flutter build windows --release
fvm flutter build linux   --release
fvm flutter build macos   --release

# 4. 命令行客户端（可选）
cd cli && dart pub get

常见问题

出问题的时候，先看这里

找不到附近的设备怎么办？

第一步：关掉路由器的 AP 隔离。多数路由器默认是关闭的，但访客网络通常打开。AP 隔离一开，同一 Wi-Fi 下的设备就互相看不见。

第二步：确认在同一个网段。5GHz 与 2.4GHz 如果被路由器拆成了两个独立网络，也会导致互相发现不了；双频合一的 SSID 一般没问题。

第三步（Windows）：把网络配置成「专用网络」，公用网络配置下系统会限制入站连接。

传输速度很慢，怎么提速？

优先使用 5GHz 频段，并在两端都关闭传输加密 —— 加密会直接吃 CPU，在小文件多、机型老的情况下尤其明显。

Android 端接收速度偏慢是一个已知问题，与系统存储访问框架（SAF）的实现有关，是上游问题。

需要放行哪个端口？

只需要放行 TCP/UDP 59420 的传入连接；传出方向保持「任意允许」即可。企业网络或第三方防火墙（如 Windows Defender 防火墙、安全软件）如果没有自动放行，手动添加一条规则就能解决。

YiDrop 会上传我的文件或数据吗？

不会。传输完全发生在你的局域网内部，数据不经过任何中转服务器，应用本身也没有账号体系、广告和追踪 SDK。

需要说明的是，操作系统层面仍然可能收集应用的使用数据（崩溃报告、电量统计之类），这与 YiDrop 无关。

怎么把设置和数据随身携带？

在可执行文件同目录放一个名为 settings.json 的文件（内容可以为空），YiDrop 就会把设置保存在这个文件里，而不是用户目录 —— 这就是便携模式。适合放在 U 盘里在不同电脑之间来回用。

如何静默启动？

启动时加上 --hidden 参数即可：程序只驻留在系统托盘，不弹主窗口，接到别人发来的文件时再跳出来确认。
